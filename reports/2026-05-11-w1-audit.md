## Audit 3 — Lubų >3m diagnosis

Ran a live scan against the interior-scope test corpus
(`/Users/ignasgaldikas/Desktop/test_pdfs/`): projektas_1, projektas_3,
projektas_4 (two brėžiniai files), vidaus_apdaila.

**Result on ALL 5 interior PDFs: 0 text-layer markers found.**

| PDF | Pages | Markers from text layer |
|-----|-------|-------------------------|
| projektas_1_breziniai.pdf | 65 | 0 |
| projektas_3_breziniai.pdf | 45 | 0 |
| projektas_4(1)_breziniai.pdf | 2 | 0 |
| projektas_4(2)_breziniai.pdf | 7 | 0 |
| vidaus_apdaila.pdf | 17 | 0 |

**The "scan all pages" assumption is INVALID for interior PDFs.** Either:
- The text layer is flattened/rasterized (CLAUDE.md already flagged this:
  "all 3 LT test PDFs are flattened raster" — `2026-04-28-pdf-spike-findings.md`)
- Or the interior projects simply lack pjūvis pages with `+X.XXX` text
  annotations (interior scope often doesn't include sections)

**Implication for the W1 Day 1 fix:** the change at `vision_call.py:2231-2275`
is technically sound (scans wider, less aggressive override) but **on
this corpus the scanner returns nothing**. The fix's real value is the
defensive parts:
- Asymmetric threshold guard (only override "going up" when cand_m > 2.95)
- Diagnostic emit on zero markers — now we KNOW when the scanner is blind

**The actual production bug — lubų >3m on a flattened interior PDF —
requires Vision-based marker reading**: the Vision call must read `+3.200`
annotations from the rendered drawing image, not from a non-existent
text layer. This is a different fix than the one shipped W1 Day 1.

**Diagnosis:**

The scanner (`height_markers.scan_page_height_markers`) works correctly. The bug is in `vision_call.py:2243`:

```python
section_pages = tuple(sorted({
    int(p["nr"]) for p in (parsed.get("puslapiai") or [])
    if (p.get("tipas") or "").lower() in ("section", "ceiling_plan")
}))
scan_pages = section_pages + ((1,) if 1 not in section_pages else ())
```

**Real LT PDFs put pjūviai on BACK pages (p36, p119, p128) — NOT p1.** Verified across 3 of 4 test PDFs.

For section markers to be found, BOTH of these must be true:
1. Vision page_classifier must tag the back page as `"section"` or `"ceiling_plan"`
2. The marker must be in the text layer (not flattened raster)

Both are fragile. In particular:
- Vision classifies pages it actually receives. If only the first N pages are sent to Vision (cost optimization), back-page sections are silently ignored.
- Flattened/rasterized PDFs (CLAUDE.md "all 3 LT test PDFs are flattened raster") may have NO extractable text — scanner returns silently empty.

**Override threshold issue (secondary):**

```python
should_override = (
    section_h is None
    or float(section_h) < cand_m - 0.3
)
```

If Vision returns 2.80 and the real marker is 3.00, diff = 0.20 < 0.3 → no override. So **3.00m ceilings stay as 2.80m** silently.

**Proposed fix (W1 Day 1 afternoon, ~30 min):**

1. **Scan ALL pages**, not just classifier-tagged:
   ```python
   import pdfplumber, io
   with pdfplumber.open(io.BytesIO(pdf_bytes)) as doc:
       num_pages = len(doc.pages)
   scan_pages = tuple(range(1, num_pages + 1))
   ```
   Cost: ~50ms per page in pdfplumber text extraction. For 139-page PDF, ~7s — acceptable one-time fallback.

2. **Tighten override threshold for "going up"** (asymmetric guard):
   ```python
   should_override = (
       section_h is None
       or float(section_h) < cand_m - 0.15   # was 0.30
   )
   # AND prevent false override on Soviet 2.50m default
   if cand_m < 2.60 and section_h is not None and abs(section_h - cand_m) < 0.20:
       should_override = False  # likely a beam, not ceiling
   ```

3. **Diagnostic emit on zero markers** for raster PDFs:
   ```python
   if not markers:
       _emit({"event": "no_height_markers", "reason": "text_layer_empty_or_flattened",
              "scan_pages_count": len(scan_pages)})
   ```

**Acceptance after W1 Day 1 fix:** for any interior PDF whose text
layer IS extractable AND contains `+X.XXX` markers, the fallback now
fires from any page (not just classified-section pages or p1).

**Real-world acceptance pending:** the 5-PDF interior corpus has zero
text-layer markers (all flattened-raster), so the W1 fix doesn't move
the production bug. The actual fix path is **Vision-side marker
reading** — a Vision prompt instruction asking the model to look for
`+3.XXX` / `+2.XXX` annotations on section / lubų plan pages and
return the largest in-range value as `lubu_aukstis_m`. Defer to W2.

**Risk:** scanning all pages may pick up a "+3.500" annotation from a legend or floor schedule that isn't a real ceiling. Mitigation: `best_ceiling_candidate` already requires `2.0 ≤ value ≤ 4.5`; a stray legend value would have to fall in this range, which is unusual.
