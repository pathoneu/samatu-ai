# Patikra — P0 contribution ledger + v1 guided audit loop — Implementation Plan

> **For agentic workers:** execute task-by-task; every task ends with the full gate suite
> (see "Global gates"). Founder approved the direction on 2026-09-02 ("okay, šitas atrodo
> gerai, bandyk daryt šitą"). The design and every data-reality fact this plan relies on
> live in `docs/superpowers/research/2026-09-02-calc-transparency-options.md` (§1 data
> reality, §3 P0 + Option A/B/C, §4 first slice, §6 batch interactions, §7 the v2 reframe).
> Read §1.2–1.4, §3 P0, §4 and §7 before touching code. Mockup (same URL as the design
> review): https://claude.ai/code/artifact/5fe2f0da-9294-4b55-be0a-5bc59e8107d0

**Goal:** every sąmata line becomes auditable and fixable in one loop — the contractor
sees which rooms/terms produced a number, which rooms were excluded and why, reaches the
control that changes the wrong input, and every ✓/fix visibly feeds the learning loop.

**Architecture:** the builder (`_build_pozicijos_from_rooms` in
`backend/extractor/vision_call.py`) EMITS provenance (`id`, `contributions[]`,
`excluded[]`, `roll_up[]`) — never reverse-engineered from labels downstream (that is
how `interior_v8/_build_trace_links` drifted). The frontend renders the server's ledger
verbatim and never re-derives Σ on the client (§1.4: old blobs already fail the Σ check).
The guided loop (Patikra) is a renderer over that ledger + the existing review-queue
ranking (`lib/takeoffWorkflow.js:rankReviewRows`, € impact × confidence), the existing
recompute endpoints, and the existing correction log.

**Non-goals for this plan:** openings/symbols positions on the drawing (no coordinates
exist — §1.5), zoom-to-region in the viewer (v2), the automatic „jūsų standartai" priors
(v2 — needs ≥3 repeated corrections per user to even trigger; design it after real
correction volume exists), the room-graph lane.

**Prerequisite:** the Contractor Feature Batch is fully landed (it is — a8ca0cd) and
pushed. P0 refactors the builder; nothing else may be editing it concurrently.

**Global gates (every task):** backend `SAMATU_AUTH_DISABLED=1 ../venv/bin/python -m
pytest -q` (baseline 2798 passed / 3 skipped — only ADD); frontend `npm run test:units`
(baseline 479; node:test runner, not vitest); `npx vite build`; eval
`venv/bin/python eval_harness.py --totals-only --recompute` from repo root — **bit-identical
7.82% (berzas 3.10 / objektas_b 19.64 / ciurliu 7.46 / lazunu 2.26)** for every P0 task
(provenance is additive; quantities must not move); reasons guard
`backend/tests/test_confidence_reasons_are_for_the_user.py`; all UI text Lithuanian, lt+en
i18n both updated; no `git push` by workers.

## Task 1 — Stable position ids [backend + both merge layers]

**Files:** `backend/extractor/vision_call.py` (builder tail, `_consolidate_paint_pozicijos`,
`_extract_medziagos_section`, `_emit_v8_compat_fields`), `backend/api/recompute_quantities.py`
(`_price_index`, `_merge_user_edits`), `frontend/src/lib/mergeDarbuSarasas.js`, tests.

- `position_id(skyrius, aprasymas)` = short stable hash (e.g. 12 hex of sha1) over
  `normalize_skyrius(skyrius)` + the tier/Q/coat-stripped label (`_norm_label` — the SAME
  normaliser the price index already uses, so the id is stable across iki/virš re-tiering
  and `(N sluoksnis)` relabels). Pure function, unit-tested for stability + collision-freedom
  across the reference project's ~130 lines (incl. the 43 Medžiagos rows — labels are already
  unique there by construction, keep the disambiguation guarantee).
- ONE assignment pass at the very end of building (after consolidation, Medžiagos
  extraction and `apply_confidence`): every pozicija gets `id`. `_emit_v8_compat_fields`
  allow-list carries `id`.
- Merge layers: both `_merge_user_edits` (backend) and `mergeDarbuSarasasEdits` (frontend)
  gain a pass 0 that matches prior↔rebuilt by `id` when BOTH sides carry one; label
  passes stay as the fallback for old blobs (no ids) and for user-added rows (assign ids
  to user rows on creation too — `insertRowInSection`/`handleAddRow` set `id` via the same
  hash; a hand-typed label collision with an auto row is fine because sections differ or
  the hash differs).
- Existing rename maps (exact-label, 42163b2) keep working: the id of a renamed line is
  computed from the NEW label, so pass 0 will not match old→new; pass 1's rename map must
  run BEFORE pass 0 is declared a miss — order: rename-map → id → label. Test it with the
  real 73-row priced demo blob (the one 42163b2 verified): every price survives, total €
  unchanged.
- Guard: a test that rebuilding the same rooms twice yields identical id sets.

## Task 2 — Contribution ledger, three families [backend]

**Files:** `backend/extractor/universal_rules.py` (kampai sub-terms), `backend/extractor/
vision_call.py` (builder emit sites for paint, kampai, grindjuostės; consolidation;
`_emit_v8_compat_fields`), `backend/api/recompute_quantities.py` (the same fields must
survive the recompute path), new `backend/tests/test_contribution_ledger.py`.

Ledger shape on a pozicija (exact keys — the frontend depends on them):
```python
"contributions": [{"room_nr": "110", "room_name": "Miegamasis", "page": 2,
                   "value": 58.0, "unit": "m",
                   "terms": {"sienos": 11.2, "angos": 15.3, "pusines": 5.6, "perimetras": 13.5},  # optional
                   "included_because": "dažoma patalpa",          # LT, guide-not-confess
                   "geometry": "polygon" | "marker" | "none"}],
"excluded": [{"room_nr": "105", "room_name": "Garažas", "excluded_because": "nedažoma pagal paskirtį"}],
"roll_up": [{"op": "sum", "label": "Σ 11 patalpų", "value": 501.3},
            {"op": "cap", "label": "riba 0,65 m/m²", "value": 107.67, "note": "…"}]
```
`roll_up.op ∈ {sum, cap, share, coefficient, constant, anchor}`. The last roll_up value
MUST equal `kiekis`. Families with no per-room driver emit `contributions: []` and a
populated `roll_up` (honestly un-decomposable) — but this task wires only:
1. **Paint** — `walls_paintable_m2` / `ceiling_paintable_m2` per room, with the per-room
   iki/virš-3m split PERSISTED (turn `_room_virs_3m_paint` into a stored per-room field
   written by `_recompute_per_room_via_python`, read by consolidation). Ceiling line with
   an eksplikacija anchor: `roll_up = [anchor 165.61, deduction −24.30 (įtempiamos lubos:
   110), result 141.31]` — reuse the exact provenance string 42163b2 already renders.
   Stretch rooms and non-painted rooms land in `excluded[]` with the LT reason.
2. **Kampai** — restore the four sub-terms deleted at `universal_rules.py:~1829`
   (inner corners × H, opening reveals Σ(W+2H), pusiniai × H, + perimeter) as persisted
   per-room fields; `terms` on each contribution; total unchanged (eval gate).
3. **Grindjuostės** — Σ per room then the 0,65 m/m² cap as a `cap` roll_up; per-room
   contributions pro-rated when capped, with `note` saying so.
- `_emit_v8_compat_fields` allow-list carries `contributions`, `excluded`, `roll_up`,
  `_assumption` (currently dropped — §1.3).
- The recompute endpoint (`/api/recompute-quantities`) rebuilds pozicijos through the
  same builder, so the ledger refreshes on every Prielaidos edit for free — add a test.
- **Guard test (the keystone):** for every corpus fixture (`ground_truth/*/ai_extract.json`
  + the demo blob) and every wired family: replay `roll_up` over `contributions` and
  assert `abs(result − kiekis) ≤ 0.01`. Assert against roll_up, NOT raw Σ (the anchored
  ceiling fails a naive Σ by construction).

## Task 5 — Patikra v1: the guided loop [frontend + small backend]

**Files:** `frontend/src/components/project/ReviewQueueSidebar.jsx` (exists), new
`PatikraCard.jsx`, `frontend/src/lib/takeoffWorkflow.js` (sensitivity + trust helpers, tested),
`AssumptionsPanel.jsx` (`focusField` prop + DOM anchors — `data-assumption="lubu_auksciai:110"`
etc.), `SanityWarningsBanner.jsx` (generalise its existing jump), `frontend/src/lib/
projectStore.js` (correction counter read), i18n; backend: `GET /api/projects/{id}/corrections`
(exists as `db.list_corrections` — expose if not already routed).
- **Queue:** `rankReviewRows` order (unchanged). Header strip: `Nepatikrinta rizika: X €`
  (Σ kiekis×kaina over rows that `needsTakeoffReview`), `liko N`.
- **Trust meter** = share of € (or kiekis before prices) in rows that are
  `user_verified_at` / `_review_status === 'accepted'` / manual — a pure function in
  takeoffWorkflow.js with tests. Label „Patikimumas".
- **Card** = row name + kiekis + € + confidence; the roll_up headline; **„Jautriausia
  vieta"** = the single largest contribution's assumption-sourced term (derive from
  `terms` + per-room source fields: `lubu_aukstis_saltinis`, `plotas_saltinis`; fall back
  to `_confidence_reason`); „kodėl toks skaičius?" opens Task 4's panel.
- **Verbs:** „Teisinga ✓" → existing accept (`acceptPositionQuantity`) + `user_verified`
  on the row; „Pataisyti" → jumps to the fix surface for the sensitive input: height →
  Prielaidos focused on that room (new `focusField`), painted/stretch → the toggle grid
  row, area/perimeter → the room's editor in the workspace, else inline kiekis edit.
- **Ripple:** after a recompute returns, diff prior vs rebuilt `darbu_sarasas` (by `id`)
  and show „Perskaičiuota: N eilučių · ±X €" (toast + a „paskutinis pataisymas" card in
  the rail). Pure diff helper, tested.
- **„Įsiminta mokymui":** every correction already lands in the `corrections` table;
  show the per-project counter („pataisymas Nr. 7") on the card and a „Mokymosi žurnalas"
  list (this project's corrections, newest first) behind a link. Copy must not overclaim:
  „Įsiminta" = recorded; nothing about global model changes.
- Rows already verified leave the queue; queue empty → „Visos svarbiausios eilutės
  patikrintos" + trust meter.
