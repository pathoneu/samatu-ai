# Pathon v3 — Wave 1 implementation plan: workspace frame, click model, overlay vocabulary, room tool, sheet zones

> **For agentic workers:** execute your track only; the manager (session "Togal-v2 backend manager") reviews and merges. Non-negotiables: `docs/superpowers/plans/2026-10-18-pathon-v3-program.md`. Design contract: `docs/superpowers/specs/2026-10-18-pathon-v3-design.md` (§3 workspace, §5 click vocabulary, §6 frame and overlay vocabulary, §9 decisions). Evidence for every "today" statement: `docs/superpowers/research/2026-10-18-pathon-viewer-ui-audit.md` (file:line cited there; re-verify lines as you go).

**Goal:** after wave 1 the founder opens demo-objektas_h in one workspace where the drawing is always present, selects rooms by clicking them, gets a wall-exact outline from one click, uses icon tools with keys and a cursor hint, sees one overlay vocabulary, has Undo after every save, confirms a sheet's scale in one click — and every number is unchanged (eval gate identical, W0-A smoke green).

**Architecture:** no engine change. Frontend restructure of `InteriorWorkspace.jsx` into a persistent canvas + right-panel mode host; `TakeoffViewer.jsx` keeps its engine (EmbedPDF/PDFium) and layers, gets a new chrome (icon cards, bottom pill, floating action bar) and the click model; overlay styles move to tokens; the vector `outline_at` route is wired into the viewer; `room_outline.py` saves return the previous geometry for Undo. Backend track E adds `extractor/sheet_zones.py` behind one GET route, consumed by nothing in the UI yet (wave 2).

**Order and isolation:** W1-A (frame), W1-C (overlay vocabulary) and W1-E (sheet zones) start in parallel — they touch disjoint files (A: InteriorWorkspace/step rail/right panel host; C: layer components + index.css tokens; E: backend). W1-B (click model) and W1-D (room click + Undo + scale chip) branch off togal-v2 **after W1-A is merged**, because all three change `TakeoffViewer.jsx`. Each track: one worktree, own ports (programme doc table), small commits, W0-A smoke run before reporting.

**Tech:** React 18 + Vite + Tailwind + shadcn, EmbedPDF 2.14.4, lucide icons; node:test for `lib/*.js`; FastAPI + pytest; Playwright e2e from W0-A.

## Track W1-E — Sheet zones backend (`v3/sheet-zones`, 8127 / 5207)

**Files:** create `backend/extractor/sheet_zones.py`, `backend/api/sheet_zones.py`, `backend/tests/test_sheet_zones.py`, `backend/tests/test_sheet_zones_api.py`; register the router in `backend/main.py` (one line); extend `tests/synthetic_plan.py` with a legend block and a table if needed (no client data). Read first: the inventory §1, §4, §6, §8 and gaps (`…-backend-reading-inventory.md`), `extractor/pdf_page_cache.py`, `pdf_vectors.py`, `pdfplumber_eksplikacija.py` (`find_tables` use), `page_classifier.py:49` (title-block crop), `api/page_geometry.py` (wall solid extent), `room_locator.py` (0.88 cut).

- [ ] **E1. Module.** `detect_zones(pdf_bytes, page) -> list[Zone]` with `Zone = {kind: 'planas'|'legenda'|'lentele'|'antspaudas'|'pastabos'|'kita', bbox_pct: [x0,y0,x1,y1] in the PDFium display frame, label: str|None, confidence: 'read'|'assumed', evidence: {source: 'teksto_sluoksnis'|'vektoriai'|'lentele'|'antspaudo_kirpimas', detail: str}}`. Signals (€0): wall-solid extent (`page_geometry.wall_solid_rings`) → `planas`; `find_tables` rectangles with ≥ 3 rows → `lentele` (label = header text); text blocks whose heading matches `SUTARTINIAI ŽENKLAI|ŽYMĖJIMAI|LEGENDA|SUTARTINIAI ŽYMĖJIMAI|PAAIŠKINIMAI` and whose rows start with a small glyph (vector path or coloured fill ≤ 12 pt) → `legenda`; the existing title-block crop confirmed by the `dalis` regex → `antspaudas`; dense text blocks outside all of the above → `pastabos`. Two plan viewports on one sheet are two `planas` zones. Pure function, PDFium under `PDFIUM_LOCK`, no model calls.
- [ ] **E2. Tests on synthetic plans.** Extend `tests/synthetic_plan.py` with an optional legend block (3 rows: coloured square + text, hairline circle + text, black cross + text) and a 4-row table; assert zone kinds and bboxes within 2 % of the drawn positions; assert a sheet without a legend yields no `legenda`; assert the title block is found at the standard position. Then run against the untracked corpus PDFs (`docs/superpowers/fixtures/`) in a non-asserting report script that prints per sheet the zones found; paste the summary in the report (no client names; use objektas codenames).
- [ ] **E3. Route and storage.** `GET /api/projects/{project_id}/pages/{page}/zones` (ownership before anything; cached per project PDF digest like `page_geometry`); `apply_geometry` stores `_meta.zonos[page]` on the free re-read / detect-run **without changing any room key** (a new lane stage is NOT added in this wave — keep `LANE_VERSION` unchanged; zones are an addition the merge logic ignores). Ownership-policy test passes.
- [ ] **E4. Consumers prepared, not wired.** Document in the module docstring the three frames (pdfplumber page, PDFium display, unrotated mediabox) and provide `zone_to_mediabox_pt(zone, page_size, rotation)` with a test, so wave 2 can place boxes in the viewer's measurement space.
- [ ] **E5. Gate.** `venv/bin/python eval_harness.py --totals-only --recompute --gate` and `--rows --recompute --gate` from the repo root: lines identical (quote them). Full backend suite before reporting.

**Risks:** raster-only sheets return `[]` with `evidence.detail = 'nėra teksto sluoksnio'` — never guess; `find_tables` can see the room table as a legend — the heading rule decides, and ambiguity yields `kita` with the detail.
