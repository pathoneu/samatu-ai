## §1 Why

Measured on `objektas_h` (fresh read, 2026-10-26):

- Full Pass-1 voting: 3 rounds × ~170 s = ~510 s.
- Zoom: 87 s (9 attempted / 0 applied — all rooms were in the eksplikacija table).

- Total: 735,4 s (`_meta.elapsed_s`).

The narrow Pass-1 (§0 of the narrow doc) would have saved the output-token tail but invented
opening sizes and missed LED niches — accuracy WORSE on both gate projects (d rows ±10 % 14 % →
12 %, d reveals −6,4 % → −41,5 %; b rows 1,8 % → 0,9 %, b reveals −10,6 % → −36,9 %).

The parallel-voting lever costs nothing in accuracy (identical prompts, identical model, results
re-ordered back into round order before voting). The zoom-skip lever costs nothing for table-read
projects because the 2026-10-25 rule already returns `zoom_wanted = False` for all such rooms.

## §3 Parallel voting facts

`ENABLE_PARALLEL_VOTING=1` fires all three voting rounds in a `ThreadPoolExecutor` instead of
one after another. The results are collected into a slot-indexed list and read back IN ROUND
ORDER — never completion order — so the median sees the same sequence it does today.
`runs[0]` stays round 1's output (the base for the voted `_meta`). Accuracy is unchanged by
construction.

**`PARALLEL_VOTING_WARM=1`** (round 1 alone, then the rest):
- Round 1 runs alone first. It writes the image prefix into the Anthropic prompt cache.
- Rounds 2..n fire concurrently after round 1 completes. They read the cache at 0.1× input cost.
- Latency: roughly one round length + the parallel tail (≈ one round) = ~2 rounds instead of 3.
- Cost: unchanged vs today (cache hit on rounds 2..n, same as serial mode).

**Without `PARALLEL_VOTING_WARM` (full parallel — image-only payloads):**
- All rounds fire at once.
- Every round pays the full image prefix as a cache write (not a read), because the first
  write has not completed before the second request arrives.
- Cost: up by roughly 2× the image prefix (rounds 2 and 3 each pay the write price instead of
  the read price). Latency: roughly one round length.

**Native-PDF payload (`b64` present):**
- Round 1 is forced to run alone regardless of warm mode (code: `_solo_first = _warm or bool(native_pdf and native_pdf.get("b64"))`).
- Reason: `_flip_to_image_fallback` mutates the shared native_pdf dict. If all rounds fired at
  once, each would burn its own document attempts; the in-place flip would also race sibling
  threads reading the dict mid-build.
- Concurrent rounds each receive a shallow copy — a flip in one round never affects another.

Covered by `backend/tests/test_parallel_voting.py` (8 tests confirmed sufficient — see §5).
