## 0. Pushback first — the premise of item 1 was half right

„Today `extract_interior` reads with the model and only the free re-read runs the geometry lane" is **not what the code
did**: `extract_interior` has called `geometry_lane.apply_geometry` at Step 2.44d since 2026-09-19 — the same function
the free re-read calls — after room identity (Step 2.4) and before the per-room math. Every fresh paid reading already
had the lane's outlines, drawn perimeters, openings and scale provenance.

What was true is the **eval**: the plain `--recompute` tail never ran Steps 2.44–2.44d; it scored the lane output frozen
into each old `ai_extract.json` (most of them older than the lane), and only `--replay-geometry` ran a hand-copied
version of the sequence. That is the whole „no drawn perimeter on plain, none on replay" gap of eval-answers §4. So item 1
became: **one function for the lanes, called by the paid reading and by the eval** — the plain pass now reads the drawing
exactly as a fresh reading does, and the copy in the harness is gone. The free re-read keeps calling `apply_geometry`
(+ the new height reader): the 2.44 text lanes (area labels, rectangle pairs, raster outlines) work on the reading's fresh
room list, which a stored project no longer has; widening the free re-read to them would change what lands on stored
projects and was not asked for.

## 1. What changed

**`backend/extractor/drawing_lanes.py` (new) — `run_drawing_lanes(parsed, pdf_bytes, emit=)`.** Steps 2.44 → 2.44d moved
out of `extract_interior` statement for statement (text scan → designer's figures + walls / floors anchors; area-label
lane when no table merged; rectangle pairs; raster outlines; geometry lane), plus the text heights **before** the
geometry lane (its open-space rule „rooms whose ceilings differ are not shared by floor area" used to read the model's
heights) and **after** it (an altitude is placed by the outline that holds it). Writes `_meta.braizinio_skaitymas` =

**`backend/text/heights.py` (new) — `apply_text_heights(parsed, pdf_bytes, statements=)`.**
1. Every height that is not his (`_overrides.lubu_auksciai`, `user_override`, `manual`) comes off the room; the model's
   figure is kept as `_lubu_aukstis_modelio` (+ its label), the model's per-room maps as `_lubu_auksciai_modelio` —
   used by nothing but the zoom pick (below).
2. Per room: the altitude printed inside the room on the ceiling plan (`ceiling_plan_marker`, the existing positioned
   lane, now never „raise-only" against a model figure — there is none); the text-layer room table's height column
   (`patalpu_lentele`, new legal source; a model-read table is not taken); a height the plan writes for one room
   (`plano_uzrasas`: H-stamps tied by the existing `_tie_statement`, and „<room> lubų aukštis 2,8 m" lines that name
   exactly one room).
3. Per project, one rule — the first that has anything to say; if its values disagree, no height and the candidates are
   listed (a weaker rule is never asked after a stronger one disagreed): an untied storey statement („patalpų aukštis
   2700 mm", „Lubų aukštis 2,80 m"); else the section / elevation altitudes when they give ONE value in 2,2–4,5 m
   („+2.800"; sheets classified section/facade/wall_elevation, or every sheet but the ceiling plans when unclassified);
   else bare untied stamps that all agree („H - 2820"). The rooms without their own take it as `projekto_aukstis`
   (new legal source, self-describing so it survives the free re-read's room merge); the project gets
   `lubu_aukstis_m` + `_lubu_aukstis_saltinis = pjuvio_zymuo` and the info warning naming the string and sheet.
4. Nothing written → the room keeps no height; Step 2.885 (`fill_heights_from_read`) and the one question „Kokio
   aukščio lubos?" are unchanged — except a tie: two heights read equally often (objektas_a 3,4 / 3,4 / 2,8 / 2,8 on
   label proximity) no longer hand the first room's value to the rest by list order; they wait for the answer.
   Provenance on every room with a height: `aukstis_saltinis` = {kaip, lapas, tekstas}; summary in
   `_meta.aukstis_tekstas` (project + rule, candidates, per-room rule, rooms without, OCR sheets, seconds).
   Behind `SAMATU_OCR` a sheet with no text layer is OCR'd locally (text/ocr.py) for the statements and the section
   altitudes. A typed / project height is not GKP-ceiling evidence (only `ceiling_plan_marker` is — Phase 3b rule kept).

## 6. For the manager

1. **The zoom pick still follows the model's own height reading** (to keep the paid crop count identical). With heights
   off the zoom, the „height not resolved → zoom" condition has no purpose; dropping it skips the zoom on every
   table-anchored room (objektas_h: 9 → 0 crops) but also loses what the zoom still writes there (a model tile height,
   niche metres) — a measured decision, not mine.
2. **b's ceiling row is now one row at the room-table total** because no room has a height. Whether an unknown height
   should keep the iki / virš 3 m split as blank rows (asking) instead of one billed row is a builder rule (3b
   territory) worth a decision; the drawing does show a double-height living room that its text does not write.
3. **d's height is read from two bare „H - 2820" stamps tied to no room** (rule 3). The 2026-10-05 rule stopped such a
   stamp from setting rooms that carried our default; here no room has any other height and every bare stamp agrees.
   If you want bare stamps never to be a project height, it is one line in `project_height` — d's walls stay blank either
   way today (no outline).
4. `apply_positioned_marker_heights` still picks the ceiling-plan sheets from the model's page classification and
   places markers by the model's boxes when there are no outlines (pre-existing; the second look after the lane uses the
   vector outlines first).
5. `vision_call._apply_per_room_heights` is now unused by the pipeline (tests still exercise it); delete with the rules
   split if you agree.
