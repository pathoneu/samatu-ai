## What this means

Promotion candidates are gated at:

- **N ≥ 3 projects** with the same metric calibrated
- **IQR ≤ 0.05** (corrections cluster tightly)
- **100% direction consistency** (all push the same way)
- **|median - 1| > 0.005** (meaningful shift, not noise)

Until those gates pass for a given metric, factors stay per-project.
This is intentional: promoting an averaged factor across contractors
with different scope conventions would corrupt the formula for projects
whose contractor didn't share that convention. (See `docs/scope_pattern_report.md`
for the per-contractor scope variation across 6 Rangovas A sąmatos.)

## Additional gate: cross-contractor data

Even when the numeric gates above pass, the calibration_learner cannot
recommend a global `formulas.yaml` change while all calibrations come
from a single contractor. The current N=6 contractor-validated benchmark
is **single-contractor** (Rangovas A / Rangovas A). Cross-contractor
data is the next blocking item.
